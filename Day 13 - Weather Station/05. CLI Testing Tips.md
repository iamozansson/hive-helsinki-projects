# CLI Testing Tips

A Command-Line Interface (CLI) is a text-based interface used to interact with a computer's operating system or software.

CLIs allow users to execute commands by typing them into a terminal or command prompt, providing a way to perform tasks, automate workflows, manage systems and more.

## Error output is displayed with diff

`diff` is a command line tool used to compare the contents of two files line by line.

When you submit your CLIs to be tested, if there are errors, the differences between the actual and expected outputs will be highlighted using `diff`.

You can use `man diff` to learn more about the command.

### Example

```bash
cat actual
cat expected
diff actual expected
```

The `diff` output uses the following notation:

* `d` → delete/remove
* `a` → add/insert
* `c` → change

For example:

```text
5d4
```

means that line 5 should be removed.

```text
15a16,17
```

means that lines 16–17 should be added.

```text
11c11
```

means that line 11 should be changed.

## Error output displays stdout only

Streams are used for communication between a program and its environment.

There are three streams:

* `stdin` → Takes user input from the terminal and provides it to the program.
* `stdout` → Takes what the program prints and displays it in the terminal.
* `stderr` → Similar to `stdout`, but used for error messages. We don't need to worry about this yet.

### Example

If the CLI works like this:

```text
Enter your name
Imbi
Hello Imbi!
Enter your name
Viktor
Hello Viktor!
Enter your name
Dav
Hello Dav!
Enter your name
```

The recorded `stdin` would be:

```text
Imbi
Viktor
Dav
```

The recorded `stdout` would be:

```text
Enter your name
Hello Imbi!
Enter your name
Hello Viktor!
Enter your name
Hello Dav!
Enter your name
```

### Important

When a CLI test fails, the error output shows **stdout only**.

Therefore, when testing your CLI, pay attention to:

* Exact text
* Spaces
* Line breaks
* The order of output
* What the program prints vs. what the user enters
